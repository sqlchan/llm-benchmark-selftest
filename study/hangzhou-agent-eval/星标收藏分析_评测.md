# GitHub 星标收藏「评测」夹分析

> **数据来源**：GitHub GraphQL API 抓取（2026-11-01），共 20 个仓库；该收藏夹当前为公开状态。
> **分析目标**：看清收藏结构与覆盖度，对齐杭州 Agent/LLM 评测工程师岗位 JD，找出「该深学 / 可舍弃 / 还缺什么」。
> **同账号其他收藏夹结构**（供定位）：Agent Skills 生态 90、学习资料与教程 83、RAG 与文档解析 56、LLM 基础 54、Agent 框架与 Harness 52、Claude Code 工具链 49、其他工具 48、量化金融 27、法律大模型 15。

## 六、冗余与取舍

- **观测平台 4 选 2**：Langfuse（深学，JD 点名 + 自托管 + dataset experiment 闭环）＞ Phoenix（OTel 生态备选）＞ Opik ≈ TruLens（了解即可）。
- **综合评测框架**：OpenCompass 主深（国内 + 平台化）；Inspect 深（Agent + 沙箱）；DeepEval 深（单测化）；OpenJudge 深（rubric/grader）；EvalScope 了解（差异在性能压测）。
- **Agent 环境**：7 个都保留，但学习顺序建议 SWE-bench → Terminal-Bench/Harbor → WebArena → OSWorld → AgentCompass → bug-hunt-bench。
- **新项目**：AgentCompass（184★）、bug-hunt-bench（187★）、OpenJudge（1k★）星数低但方向新，适合作为"边学边贡献"的切入点。

## 七、五个值得注意的发现

1. **OpenJudge 与 JD 的匹配度可能是全夹最高**：50+ grader、Rubric 自动生成、Agent 生命周期（工具选择/记忆/规划/轨迹）评测、grading 结果转 reward 信号——几乎逐条对应 JD 行 9/12 的"Rubric、Grader、Verifier、LLM-as-Judge"。建议从"了解"上调为"深学"。
2. **harness2 容易被误读**：它全名是 *Recursive Agent Harnessing*，做的是自动优化 Agent harness（prompt/tools/memory/skills 等 8 个组件），自带 JobBench / LAB / WorkBuddy-Bench 三个专业任务 benchmark。它属于"Agent 能力/方法"而非"评测平台"，放错分类会浪费学习时间。
3. **iFixAi（41k★）走的是"审计"路线**：模拟业务环境 + 61 项 inspection + A-F 评级 + EU AI Act 视角，适合讲"Agent 安全/合规评测"，但偏产品化，深学价值低于 garak（红队工具）。
4. **bug-hunt-bench 代表 Coding 评测新形态**：105 个真实 bug、盲评、live leaderboard，与 SWE-bench 互补，说明"真实任务 + 防刷分"是 Coding 评测的演进方向。
5. **WebArena canonical 仓库已停更（2025-11）**：官方推荐转向 AgentLab + BrowserGym；学习时别从旧 README 起步，先看 BrowserGym。

## 九、一句话总结

**收藏质量高、前沿敏感度强**（2026 年的 AgentCompass、OpenJudge、harness2、bug-hunt-bench、iFixAi 都在），已经是"评测全链路"型收藏夹；接下来最大的两个动作是：**补齐 JD 点名却缺失的 lm-evaluation-harness（P0）**，以及**从 20 个收藏里挑 6 个真正跑通**——收藏夹的价值不在于数量，而在于能讲出几条完整的评测链路。
